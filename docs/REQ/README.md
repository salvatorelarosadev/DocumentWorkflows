# Requirements

Repository-wide requirements live here. Project-specific requirements live in the relevant subproject.

Every requirement uses:
- stable ID;
- title;
- **Formal requirement** — normative/authoritative, preferably must/should/may;
- **Rationale / design intent** — non-normative explanation;
- **Source / origin** where known;
- optional status, acceptance criteria, notes/examples.

If formal text and rationale conflict, formal text governs. IDs are not silently renumbered or reused. See `templates/documentation/REQ.md`.
